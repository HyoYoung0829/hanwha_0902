# 0907 학습 정리

오늘은 Pydantic을 사용해서 데이터를 검증하고 변환하는 연습을 했다.

외부에서 들어온 데이터가 내가 원하는 구조와 타입에 맞는지 확인하고, 필요하면 Python에서 쓰기 좋은 타입으로 바꿔주는 흐름이다.

## 1. Pydantic 기본 모델

Pydantic 모델은 `BaseModel`을 상속해서 만든다.

```python
from pydantic import BaseModel

class User(BaseModel):
    name: str
    age: int
    email: str = None
```

이 모델은 `name`, `age`, `email`을 가진 사용자 데이터 구조를 의미한다.

```python
user = User(
    name="백효영",
    age="26",
    email="gydud7300@naver.com",
)
```

`age`에 문자열 `"26"`이 들어와도 `int`로 바꿀 수 있으면 자동 변환된다.

## 2. 외부 데이터 검증

딕셔너리 형태의 외부 데이터를 모델에 넣을 때는 `**`를 사용한다.

```python
user = User(**external_data)
```

`**external_data`는 딕셔너리를 풀어서 모델의 인자로 전달하는 문법이다.

순서가 아니라 키 이름으로 매칭되기 때문에 외부 데이터 순서는 중요하지 않다.

## 3. 기본값과 Optional

모델 필드에 기본값을 줄 수 있다.

```python
name: str = "백효영"
```

값이 없을 수도 있는 필드는 `| None`을 사용했다.

```python
signup_ts: datetime | None
nickname: str | None = None
```

`None`을 허용한다는 뜻이다.

## 4. 타입 변환

Pydantic은 가능한 경우 타입을 자동으로 변환한다.

예를 들어 문자열로 들어온 숫자를 정수로 바꾸거나, 문자열 날짜를 `datetime`으로 바꿀 수 있다.

```python
id: int
signup_ts: datetime | None
```

외부 데이터에서는 문자열이었지만, 모델을 통과한 뒤에는 지정한 타입에 맞게 변환된다.

## 5. ValidationError

데이터가 모델 규칙에 맞지 않으면 `ValidationError`가 발생한다.

```python
from pydantic import ValidationError

try:
    User(**error_external_data)
except ValidationError as e:
    pprint(e.errors())
```

`e.errors()`를 보면 어떤 필드에서 어떤 문제가 생겼는지 확인할 수 있다.

## 6. Field로 세부 조건 걸기

`Field()`를 사용하면 숫자 범위나 문자열 길이 같은 조건을 줄 수 있다.

```python
from pydantic import Field

class User(BaseModel):
    age: int = Field(ge=0, le=150)
```

회원가입 예제에서는 이런 식으로 조건을 걸었다.

```python
class SignupRequest(BaseModel):
    username: str = Field(min_length=3, max_length=20)
    password: str = Field(min_length=8)
    age: int = Field(ge=14)
```

## 7. Literal과 Annotated

`Literal`은 들어올 수 있는 값을 딱 정해둘 때 사용한다.

```python
from typing import Literal

color: Literal["red", "green"]
```

이 경우 `color`에는 `"red"` 또는 `"green"`만 들어올 수 있다.

`Annotated`는 기본 타입에 추가 조건을 붙일 때 사용한다.

```python
from typing import Annotated
from annotated_types import Gt

weight: Annotated[float, Gt(0)]
```

이 예제에서는 `weight`가 실수이고 0보다 커야 한다는 뜻이다.

## 8. 중첩 모델

모델 안에 다른 모델을 넣을 수 있다.

```python
class Address(BaseModel):
    city: str
    zip_code: str

class User(BaseModel):
    name: str
    age: int
    email: str
    address: Address
```

입력 데이터에서는 `address`가 딕셔너리로 들어와도, Pydantic이 `Address` 모델로 변환해준다.

```python
user.address.city
```

이렇게 객체처럼 접근할 수 있다.

## 9. 복잡한 타입

리스트, 딕셔너리, 튜플 같은 타입도 모델 필드로 사용할 수 있다.

```python
bazam: dict[str, list[tuple[int, bool, float]]]
```

처음 보면 복잡하지만, 안쪽부터 보면 된다.

- `tuple[int, bool, float]`: 정수, 참/거짓, 실수로 이루어진 튜플
- `list[...]`: 그런 튜플들이 들어있는 리스트
- `dict[str, ...]`: 문자열 키를 가진 딕셔너리

## 10. model_dump

Pydantic 모델 객체를 일반 딕셔너리로 바꿀 때 `model_dump()`를 사용한다.

```python
m.model_dump()
```

옵션을 주면 필요한 형태로 조정할 수 있다.

```python
m.model_dump(exclude_unset=True)
m.model_dump(exclude={"where"}, mode="json")
m.model_dump_json(exclude_defaults=True)
```

자주 나온 옵션은 다음과 같다.

| 옵션 | 의미 |
| --- | --- |
| `exclude_unset=True` | 직접 넣지 않은 값은 제외 |
| `exclude={"where"}` | 특정 필드 제외 |
| `mode="json"` | JSON으로 쓰기 좋은 형태로 변환 |
| `exclude_defaults=True` | 기본값과 같은 필드 제외 |

## 오늘의 핵심 요약

- Pydantic 모델은 데이터 구조를 정하고 검증한다.
- 외부 딕셔너리는 `**`로 풀어서 모델에 넣을 수 있다.
- 타입이 맞지 않으면 `ValidationError`가 발생한다.
- 가능한 타입 변환은 Pydantic이 자동으로 해준다.
- `Field()`로 길이, 범위 같은 세부 조건을 줄 수 있다.
- `Literal`은 허용 값을 제한할 때 쓴다.
- `Annotated`는 타입에 추가 검증 조건을 붙일 때 쓴다.
- 모델 안에 모델을 넣으면 중첩 데이터도 검증할 수 있다.
- `model_dump()`는 모델을 딕셔너리로 바꿀 때 사용한다.
