# 0909 학습 정리

오늘은 FastAPI를 조금 더 실제 프로젝트처럼 쓰는 내용을 배웠다.

핵심은 의존성 주입, 인증 토큰 처리, CORS, DB 연결, 라우터 분리, 테스트다.

## 1. 의존성 주입

의존성은 API가 실행되기 전에 필요한 공통 작업을 FastAPI가 대신 실행하고, 그 결과를 함수에 넣어주는 기능이다.

```python
from typing import Annotated
from fastapi import Depends

async def common_parameters(
    q: str | None = None,
    skip: int = 0,
    limit: int = 100,
):
    return {"q": q, "skip": skip, "limit": limit}

@app.get("/items/")
async def read_items(commons: Annotated[dict, Depends(common_parameters)]):
    return commons
```

`Depends(common_parameters)`는 `common_parameters` 함수를 먼저 실행하고, 그 결과를 `commons`에 넣어달라는 뜻이다.

주의할 점은 `common_parameters()`가 아니라 `common_parameters`를 넘긴다는 것이다. 지금 당장 실행하는 게 아니라 FastAPI에게 함수 자체를 맡기는 느낌이다.

## 2. 의존성을 쓰는 이유

여러 API에서 반복되는 코드를 한 곳으로 뺄 수 있다.

예를 들면 이런 작업들이 의존성으로 빠지기 좋다.

- 공통 쿼리 파라미터 처리
- DB 연결 준비
- 로그인한 사용자 확인
- 토큰 검사
- 권한 검사
- Agent 실행에 필요한 LLM이나 설정 준비

API 함수는 실제 핵심 로직에 더 집중할 수 있다.

## 3. 하위 의존성

의존성 함수 안에서 또 다른 의존성을 사용할 수도 있다.

```python
def query_extractor(q: str | None = None):
    return q

def query_or_cookie_extractor(
    q: Annotated[str, Depends(query_extractor)],
    last_query: Annotated[str | None, Cookie()] = None,
):
    if not q:
        return last_query
    return q
```

FastAPI가 필요한 함수들을 따라가면서 순서대로 실행해준다.

쿼리 값이 있으면 쿼리를 쓰고, 없으면 쿠키 값을 대신 쓰는 구조다.

## 4. 의존성 캐시

FastAPI는 한 요청 안에서 같은 의존성 함수를 기본적으로 한 번만 실행한다.

같은 결과가 필요하면 캐싱된 값을 재사용한다.

매번 새로 실행해야 한다면 `use_cache=False`를 사용할 수 있다.

```python
Depends(get_value, use_cache=False)
```

## 5. 데코레이터에 의존성 걸기

의존성 결과를 함수 안에서 직접 쓰지 않고, 실행만 하고 싶을 때가 있다.

예를 들어 토큰이나 키를 검사만 하는 경우다.

```python
@app.get("/items/", dependencies=[Depends(verify_token), Depends(verify_key)])
async def read_items():
    return [{"item": "Foo"}, {"item": "Bar"}]
```

이렇게 하면 `read_items()` 함수에 불필요한 파라미터를 만들지 않아도 된다.

검사용 의존성에는 잘 어울린다.

## 6. Header 검사

헤더 값을 받아서 토큰이나 키를 검사할 수 있다.

```python
async def verify_token(x_token: Annotated[str, Header()]):
    if x_token != "fake-super-secret-token":
        raise HTTPException(status_code=400, detail="X-Token header invalid")
```

요청 헤더에 기대한 값이 없으면 `HTTPException`으로 에러를 보낸다.

## 7. yield 의존성

`yield`는 API 실행 전후로 작업을 나눠야 할 때 사용한다.

대표적인 예시는 DB 세션이다.

```python
async def get_db():
    db = DBSession()
    try:
        yield db
    finally:
        db.close()
```

흐름은 다음과 같다.

1. DB 연결을 만든다.
2. `yield db`로 API 함수에 넘긴다.
3. API 함수가 DB를 사용한다.
4. 응답 처리가 끝난다.
5. 다시 의존성 함수로 돌아와서 정리 작업을 한다.
6. `finally`에서 DB 연결을 닫는다.

요청 동안 빌려 쓰고, 끝나면 정리해야 하는 자원에 잘 맞는다.

## 8. OAuth2PasswordBearer

보호된 API에서 Bearer 토큰을 꺼낼 때 `OAuth2PasswordBearer`를 사용할 수 있다.

```python
from fastapi.security import OAuth2PasswordBearer

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

@app.get("/items/")
async def read_items(token: Annotated[str, Depends(oauth2_scheme)]):
    return {"token": token}
```

요청 헤더가 이런 형태라면:

```text
Authorization: Bearer abc123
```

FastAPI가 `abc123` 부분을 꺼내서 `token`에 넣어준다.

`tokenUrl="token"`은 토큰을 발급받는 주소가 `/token`이라는 것을 문서에 알려주는 역할도 한다. 단, `/token` API를 자동으로 만들어주지는 않는다.

## 9. 현재 사용자 가져오기

토큰을 받은 뒤, 그 토큰으로 현재 사용자를 만드는 흐름도 연습했다.

```python
class User(BaseModel):
    username: str
    email: str | None = None
    full_name: str | None = None
    disabled: bool | None = None
```

```python
async def get_current_user(token: Annotated[str, Depends(oauth2_scheme)]):
    user = fake_decode_token(token)
    return user

@app.get("/user/me")
async def read_user_me(current_user: Annotated[User, Depends(get_current_user)]):
    return current_user
```

흐름은 이렇게 보면 된다.

1. 요청에서 Bearer 토큰을 꺼낸다.
2. 토큰을 해석해서 사용자 정보를 만든다.
3. API 함수는 현재 사용자 객체를 받아서 사용한다.

## 10. CORS

CORS는 브라우저에서 서로 다른 출처끼리 통신할 때 생기는 보안 정책이다.

Origin은 다음 세 가지 조합이다.

```text
프로토콜 + 도메인 + 포트
```

예를 들어 `localhost:3000`과 `localhost:8000`은 서로 다른 Origin이다.

프론트엔드에서 FastAPI 서버로 요청을 보내려면 허용할 출처를 등록해야 할 수 있다.

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=origins,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

이 설정은 어떤 프론트 주소에서 오는 요청을 허용할지 정하는 역할을 한다.

## 11. SQLModel

이전까지는 클라이언트와 서버 사이의 통신을 주로 다뤘다면, 이번에는 서버와 DB 사이의 통신을 다뤘다.

`SQLModel`은 Python 클래스와 DB 테이블을 연결해준다.

```python
class Hero(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    name: str
    age: int | None = None
    secret_name: str
```

`table=True`를 붙이면 이 모델은 실제 DB 테이블과 연결된다.

개념적으로는 이렇게 보면 된다.

```text
Hero 클래스   <-> hero 테이블
Hero 객체 1개 <-> DB row 1개
```

## 12. Engine과 Session

DB 작업에서는 `Engine`과 `Session`이 중요하다.

```python
sqlite_url = "sqlite:///database.db"
engine = create_engine(sqlite_url, connect_args={"check_same_thread": False})
```

`Engine`은 어떤 DB에 연결할지 관리하는 객체다.

`Session`은 실제 조회, 저장, 삭제 같은 작업을 수행하는 객체다.

```python
def get_session():
    with Session(engine) as session:
        yield session
```

API 요청마다 세션을 빌려주고, 요청이 끝나면 정리되도록 `yield`를 사용했다.

## 13. CRUD 기본 흐름

DB에서 자주 하는 작업은 CRUD라고 부른다.

| 이름 | 의미 |
| --- | --- |
| CREATE | 생성 |
| READ | 조회 |
| UPDATE | 수정 |
| DELETE | 삭제 |

예제에서는 생성, 전체 조회, 하나 조회, 삭제를 다뤘다.

```python
session.add(hero)
session.commit()
session.refresh(hero)
```

저장할 때는 객체를 세션에 등록하고, 커밋한 뒤, DB에서 만들어진 최신 값을 다시 반영한다.

```python
hero = session.get(Hero, hero_id)
```

Primary Key로 하나를 조회할 때는 `session.get()`을 사용했다.

```python
session.delete(hero)
session.commit()
```

삭제할 때도 삭제 대상으로 등록한 뒤 커밋해야 DB에 반영된다.

## 14. APIRouter로 파일 나누기

API가 많아지면 한 파일에 전부 넣기 불편해진다.

이럴 때 `APIRouter`로 기능별 파일을 나눌 수 있다.

```python
from fastapi import APIRouter

router = APIRouter(
    prefix="/users",
    tags=["users"],
)
```

`prefix="/users"`를 주면 이 라우터 안의 API들은 모두 `/users`로 시작한다.

`main.py`에서는 라우터를 가져와서 연결한다.

```python
from routers import agents, users

app.include_router(users.router)
app.include_router(agents.router)
```

대략 이런 구조다.

```text
practice9/
├── main.py
├── dependencies.py
└── routers/
    ├── users.py
    └── agents.py
```

공통 의존성은 `dependencies.py`에 두고, 사용자 API와 Agent API는 각각 라우터 파일로 분리했다.

## 15. 라우터에 의존성 적용하기

특정 API에만 토큰 검사를 걸 수도 있다.

```python
@router.post(
    "/run",
    dependencies=[Depends(verify_token)],
)
def run_agent(prompt: str):
    return {
        "prompt": prompt,
        "result": f"Agent response for: {prompt}",
    }
```

이 예제에서는 Agent 실행 API에만 `verify_token`을 적용했다.

즉, Agent를 실행하려면 요청 헤더에 올바른 토큰이 있어야 한다.

## 16. TestClient

API가 많아지면 Swagger에서 하나씩 눌러보는 방식은 번거롭다.

FastAPI는 서버를 직접 띄우지 않고도 테스트 요청을 보낼 수 있는 `TestClient`를 제공한다.

```python
from fastapi.testclient import TestClient

client = TestClient(app)
```

테스트 함수에서는 실제 브라우저 요청처럼 API를 호출한다.

```python
def test_read_main():
    response = client.get("/")

    assert response.status_code == 200
    assert response.json() == {"msg": "Hello World"}
```

`assert`는 조건이 참인지 확인한다.

조건이 틀리면 테스트가 실패한다.

`TestClient`는 JavaScript에서 `fetch`나 `axios`로 요청을 보내는 것과 비슷하고, `pytest`는 Jest나 Vitest 같은 테스트 실행기로 생각하면 된다.

## 오늘의 핵심 요약

- `Depends()`는 공통 준비 작업을 API 함수에 연결하는 기능이다.
- 의존성 함수는 직접 실행하지 않고 함수 자체를 FastAPI에 넘긴다.
- 의존성 안에서 또 다른 의존성을 사용할 수 있다.
- 검사만 필요한 의존성은 데코레이터의 `dependencies`에 넣을 수 있다.
- `Header()`로 요청 헤더 값을 받을 수 있다.
- `yield` 의존성은 사용 후 정리가 필요한 자원에 적합하다.
- `OAuth2PasswordBearer`는 Bearer 토큰을 꺼내는 데 사용한다.
- CORS는 다른 Origin에서 오는 브라우저 요청을 허용할지 정하는 설정이다.
- `SQLModel`은 Python 모델과 DB 테이블을 연결한다.
- `Engine`은 DB 연결 정보, `Session`은 실제 DB 작업 담당이다.
- `APIRouter`를 쓰면 API를 기능별 파일로 나눌 수 있다.
- `TestClient`로 서버를 직접 띄우지 않고 API 테스트를 할 수 있다.
